## Workload

Four real isolated PTYs ran the deterministic Python generator for 30 seconds.
Each wrote 12 source-like lines every 100 ms, including ANSI colors, combining
text, wide characters and status glyphs. One production `CanvasTerminal` was
visible; three were hidden. This matches the retained observation's one visible
output-heavy terminal with concurrent retained sessions, not a claim that many
hidden terminals painted.

The visible container was 1878×1260 CSS pixels. Bundled application font rules
were loaded before capture. Actual final paint state: canvas 3724×2520 device
pixels, 13px font, 8×20 CSS-pixel cells, DPR 2, font weight 400, requested family
`"JetBrainsMono Nerd Font", "JetBrains Mono", "Symbols Nerd Font Mono", monospace`.
The final viewport origin was 3234, with no hidden marker rows or answer markers.
This requested family does not establish that every fallback glyph uses the
same native font as Boss's historical WebView.

The bounded recorder retained **21 events: 14 arrivals and 7 paints**, spanning
only **346.1 ms**, with **1692 events dropped**. Its global 4 MiB budget, not the
nominal ten-second window, was the binding limit. Each renderer replayed the
seven retained paint snapshots three times, giving only 21 paint samples.
**The replay is a suffix, not the entire 30-second stream.** The PTY captures
are also capped prefixes, not lossless full streams. The source generator is the
one-command means to regenerate the longer workload.

There were **zero failed independent backend probes**. The largest final
sentinel gap occurred during recording dump and subsequent revision-module
loading, not during active terminal output. The phase includes several tasks;
its 632 ms gap does not isolate one of them as the cause. It is not the
historical 30-second outage.

The earlier one-session smoke and 15-second four-session run succeeded after
two harness setup failures were corrected. Those earlier runs omitted the
application font rules and did not separate dump from capture; their raw files
remain under `smoke3/` and `workload/`, but they are not pooled with this table.
The first attempt failed when a multi-megabyte dump was forwarded to a route
absent from the headless remote router. The second failed because the revision
export omitted a settings JSON import. The final run saves the dump within the
harness and exports required JSON inputs. No production route was changed.
